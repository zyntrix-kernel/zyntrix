    28→## What is OpenDesign
    29→
    30→OpenDesign is **the 1st collaborative AI design agent workspace**. Start with a brief, then use your coding agent or OpenDesign Cloud to create a prototype that follows your design system. Share it with your team for feedback, and let your agent refine it in the same project.
    31→
    32→That workflow is open and extensible. OpenDesign is licensed under Apache 2.0 and gives teams skills, design templates, design systems, and plugins they can inspect and adapt to their own process.

   235→## Why OpenDesign
   236→
   237→- 🤖 **Agent-native, model-agnostic.** We don't ship an agent. The `claude` / `codex` / `cursor-agent` / `copilot` / `hermes` / `kimi` already on your `PATH` are the design engine. Swap with one click.
   238→- 🧠 **Brand-grade by default.** Every render reads the active package's `DESIGN.md` as the core brand contract. 151 design-system packages ship with the repo; legacy packages may be `DESIGN.md`-only, while newer packages can add `manifest.json`, `tokens.css`, components, assets, and provenance. Drop a folder in, the picker finds it.
   239→- 🖥️ **Local-first, BYOK at every layer.** Native desktop apps for macOS (Apple Silicon + Intel) and Windows (x64). Linux desktop users can currently run OpenDesign [from source](#-run-from-source); the latest official release does not include a prebuilt Linux artifact. Product analytics and session replay are consent-gated; scrubbed safety and reliability telemetry is always on. Before describing daemon data paths, contributors and operators MUST read `AGENTS.md` → **Daemon data directory contract**. This README MUST NOT restate it.
   240→- 🌍 **Composable on four planes.** **Plugins** carry runnable workflows · functional **skills** carry agent behavior · **design templates** carry rendering blueprints · **design systems** carry the brand. All four use portable, versionable directories that anyone can author and publish.
   241→- 🔁 **Refresh an existing codebase.** Hand a `git` repo + `DESIGN.md` to the agent and it refactors your real components to the brand spec.
   242→- 🔒 **Privacy by conviction.** Projects can run locally or in your own deployment. Cloud model and OpenDesign Cloud requests are sent to the corresponding services. The BYOK proxy includes SSRF safeguards.

   246→## Quick start
   247→
   248→### 🖥️ Download the desktop app (recommended — zero config)
   249→
   250→The fastest way to use OpenDesign. No Node, no pnpm, no clone.
   251→
   252→- **macOS** (Apple Silicon · Intel x64) → [**open-design.ai**](https://open-design.ai/?utm_source=github&utm_medium=referral&utm_content=readme_download_macos) or [GitHub Releases](https://github.com/nexu-io/open-design/releases)
   253→- **Windows** (x64) → [**open-design.ai**](https://open-design.ai/?utm_source=github&utm_medium=referral&utm_content=readme_download_windows) or [GitHub Releases](https://github.com/nexu-io/open-design/releases)
   254→- **Linux** → No prebuilt Linux artifact is currently published in the official releases. For now, [run OpenDesign from source](#-run-from-source); Linux release work is tracked in [#4368](https://github.com/nexu-io/open-design/issues/4368).
   255→
   256→After install: the app auto-detects every coding-agent CLI on your `PATH`, loads 100+ functional skills, the separate rendering-template catalog, and 151 design systems, and lets you type a brief in the entry view.
   257→
   258→### 🤖 Install into your coding agent (no UI)
   259→
   260→You can use OpenDesign without ever opening the GUI — call it as a skill, plugin, or MCP server inside Claude Code, Codex, Cursor, Copilot, OpenClaw, Antigravity, Hermes, Kimi, and more.
   261→
   262→If you installed the macOS desktop app via the DMG or Homebrew cask, your shell
   263→may still resolve `od` to Apple's built-in `/usr/bin/od` octal-dump utility. In
   264→that case, open **Settings → MCP server** in the desktop app and copy the
   265→client-specific snippet; it uses absolute paths and does not rely on the bare
   266→`od` command.

   284→> shadow OpenDesign's `od` command. Desktop-app users should prefer the

   331→### A full workflow — from brief to artifact
   332→
   333→`brief → plugin → direction → design system → artifact → handoff → memory`
   334→
   335→1. **A PM submits a brief.** The plugin picker offers landing page · pitch deck · dashboard · social post · PM spec · OKR scorecard…
   336→2. **A designer (or the agent) locks the direction.** No brand? Pick from 5 curated directions. Have a brand? Drop a screenshot / URL → the agent connects GitHub and codifies a reusable `DESIGN.md`.
   337→3. **The agent creates the first deliverable.** Plugin + functional skill or design template + `DESIGN.md` are bound. Filesystem-backed CLI runs write canonical project files and the preview follows them; BYOK/plain-API runs without file tools return one complete `<artifact>` block.
   338→4. **Hand off to engineering.** The artifact is real HTML/CSS — drop it into Cursor, Codex, or Claude Code to keep building as code. Or export PPTX / PDF / MP4 straight to marketing.
   339→5. **OpenDesign gets smarter as you use it.** Your screenshots, fonts, palettes, and confirmed artifacts accumulate as defaults for the next session. Less rework, less drift.

   343→## Use OpenDesign from your coding agent
   344→
   345→OpenDesign ships a **stdio MCP server** and per-agent **install scripts**. Any MCP-compatible agent in another repo can read files from your local OpenDesign projects directly — tokens CSS, JSX components, entry HTML — as a structured API queryable by name. The agent always sees the live file, not a stale export.
   346→
   347→```bash
   348→# One-line install (16+ CLIs supported):
   349→od mcp install <agent>
   350→
   351→# Then the agent can:
   352→od project list --json
   353→od files list <project-id> --json
   354→od files read <project-id> <relative-path>
   355→od plugin list --json
   356→od skills list --json
   357→```
   358→
   359→**Why MCP?** Exporting and re-attaching a zip every iteration breaks flow. MCP exposes the design source directly — the agent always sees the live file.
   360→
   361→**For an agent starting from scratch,** the installer places `~/.config/<agent>/open-design.json` (or the platform equivalent) plus a copy-paste MCP snippet. Cursor gets a one-click deeplink; Claude Code gets a `claude mcp add-json` one-liner; every other agent gets JSON in the schema its config expects. On macOS desktop installs, prefer that Settings snippet over typing bare `od mcp install <agent>` in Terminal, because `/usr/bin/od` may win on PATH. Full per-agent flow → **Settings → MCP server** in the desktop app, or [`docs/agent-adapters.md`](docs/agent-adapters.md).
   362→
   363→**Security model.** Read-only by default, the daemon binds to `127.0.0.1`, and SSRF is blocked at the proxy edge. LAN exposure requires an explicit `OD_BIND_HOST` plus `OD_ALLOWED_ORIGINS`. Connector credentials and live-artifact preview routes stay loopback-only regardless.
   364→
   365→**Internally-hosted model endpoints.** To prevent SSRF, the daemon blocks provider base URLs that resolve to private/internal address ranges (RFC1918, link-local, CGNAT, and cloud-metadata IPs) by default, surfacing `Internal IPs blocked`. If you run an internally-hosted gateway (e.g. LiteLLM or Ollama on a VPN-only `10.x`/`192.168.x` address), opt that host out with `OD_ALLOWED_INTERNAL_HOSTS=<host1>,<host2>,...` — a comma- or whitespace-separated list of bare hostnames or IPs (`10.0.0.5`, `litellm.internal.corp`; a `host:port` or full URL is accepted and reduced to its hostname; IPv6 must be bracketed, e.g. `[fd00::1]`). The allowlist is strict opt-in (empty by default), exact-host (no subdomain/substring matching), and applies **only** to provider endpoints you configure (connection test, model discovery, BYOK chat). It deliberately does **not** relax the guard on download URLs returned inside upstream responses, which stay blocked. A malformed entry — or CIDR notation, which is not supported — is dropped with a warning rather than silently trusted, so a typo never quietly widens (or fails to widen) the guard. Allowlisting a hostname trusts whatever it resolves to (like `OD_ALLOWED_ORIGINS`); allowlist the resolved IP instead if you want the DNS-resolved address re-checked.

   457→### Using plugins
   458→
   459→Plugins are at full parity across the **web UI** and the **`od` CLI** — same `/api/plugins` endpoints, pick whichever fits.
   460→
   461→**In the desktop / web app:** open the **Plugin** page to browse the marketplace and click **Install**; inside a project's Studio, plugins appear as composer chips you click to apply (with the inputs they declare).
   462→
   463→**On the command line** (runs without a UI — this is the path external agents use):
   464→
   465→```bash
   466→od plugin list                       # list installed plugins (--task-kind / --mode / --tag filters)
   467→od plugin search "landing page"      # search by keyword
   468→od plugin info od-default            # inspect a plugin's metadata, inputs, capabilities
   469→od plugin install od-default        # install from a registry; also accepts ./local-folder or an https://… link
   470→od plugin apply od-default --input brief="a one-page pitch for our seed round"
   471→od plugin upgrade od-default         # upgrade
   472→od plugin uninstall od-default       # uninstall
   473→```

   477→### Building a plugin
   478→
   479→An OpenDesign plugin requires `open-design.json` plus the payload required by its type. A workflow skill or scenario also includes `SKILL.md`; manifest-only template and design-system entries use their own payloads instead:
   480→
   481→```
   482→my-plugin/
   483→├── open-design.json    ← required: marketplace metadata + inputs + pipeline + capabilities
   484→├── SKILL.md            ← required for agent-skill/scenario entries; omitted for other plugin types
   485→├── README.md           ← optional: usage, install, registry links
   486→├── preview/            ← optional: index.html / poster.png (strongly recommended for visual plugins)
   487→└── examples/           ← optional: concrete use cases
   488→```
   489→
   490→Core `open-design.json` fields: `specVersion` (currently `1.0.0`), `name` (stable ID), `version` (semver), optional `compat.agentSkills[].path` (points at `./SKILL.md` when the entry exposes an Agent Skill), `od.kind` (`skill` / `scenario` / `atom` / `bundle`), `od.taskKind` (`new-generation` / `figma-migration` / `code-migration` / `tune-collab`), `od.mode` (the output surface, e.g. `prototype` / `deck` / `live-artifact` / `image` / `video` / `hyperframes` / `audio` / `design-system` / `scenario`), `od.capabilities[]` (**declare the minimum** — a restricted install grants only `prompt:inject` by default), `od.inputs[]` (apply-time parameters).
   491→
   492→Scaffold + validate locally:
   493→
   494→```bash
   495→od plugin scaffold --id my-plugin --title "My Plugin"   # generate the skeleton
   496→od plugin validate ./my-plugin                          # check manifest / file layout
   497→pnpm guard && pnpm --filter @open-design/plugin-runtime typecheck
   498→```

   503→
   504→1. Drop the plugin folder into [`plugins/community/`](plugins/community/) (third-party plugins), or — to ship it bundled with OpenDesign — into the matching tier of [`plugins/_official/`](plugins/_official/).

   514→
   515→```
   516→┌────────────────── browser (Next.js 16) / Electron shell ──────────────┐
   517→│  chat · file workspace · iframe preview · settings · import · MCP     │
   518→└──────────────┬─────────────────────────────────────┬─────────────────┘
   519→               │ /api/*                              │
   520→               ▼                                     ▼
   521→   ┌─────────────────────────────────┐   /api/proxy/{provider}/stream (SSE)
   522→   │  local daemon (Express+SQLite)  │   ─→ any OpenAI-compatible BYOK,
   523→   │                                  │       SSRF-guarded at the edge
   524→   │  /api/skills    /api/design-templates    /api/plugins    │
   525→   │  /api/design-systems            │
   526→   │  /api/chat (SSE)   /api/proxy/* │
   527→   │  /api/projects/:id/files/...    │
   528→   │  /api/artifacts/{save,lint}     │
   529→   │  /api/import/claude-design      │
   530→   │  MCP stdio server                │
   531→   └─────────┬───────────────────────┘
   532→             │ spawn(cli, [...], { cwd: managed project cwd })
   533→             ▼
   534→   ┌──────────────────────────────────────────────────────────────────┐
   535→   │  Local runtime definitions come from runtimes/registry.ts;                 │
   536→   │  the base registry has 27 definitions (including byok-opencode),           │
   537→   │  backed by 26 distinct local CLI executables because byok-opencode shares │
   538→   │  the OpenCode executable. See docs/agent-adapters.md.                     │
   539→   │  composes a functional skill or design template + DESIGN.md; writes files │
   540→   └──────────────────────────────────────────────────────────────────┘
   541→```

   543→| Layer | Stack |
   544→|---|---|
   545→| Frontend | Next.js 16 App Router + React 18 + TypeScript |

   549→| Export | HTML (inlined) · PDF (browser print) · PPTX (agent-driven) · ZIP · Markdown · MP4 (HyperFrames) |
   550→| Desktop | Electron shell + sandboxed renderer + sidecar IPC (STATUS · EVAL · SCREENSHOT · CONSOLE · CLICK · SHUTDOWN) |
   551→| Lifecycle | One entry point: `pnpm tools-dev` (start / stop / run / status / logs / inspect / check) |

   599→## Contributing
   600→
   601→OpenDesign keeps moving because contributors — designers, engineers, prompt authors — keep showing up. Many of the most-used skills, design systems, and plugins were written by people outside the core team.
   602→
   603→### 🎯 Where to start (max leverage, min change)
   604→
   605→| Want to ship… | How | Where |
   606→|---|---|---|
   607→| A new functional **skill** | Drop a folder with `SKILL.md` + optional `assets/` + `references/` | [`skills/`](skills/) · spec in [`docs/skills-protocol.md`](docs/skills-protocol.md) |
   608→| A new rendering **design template** | Add a renderable `SKILL.md` bundle | [`design-templates/`](design-templates/) |
   609→| A new **design system** | Drop a package centered on `DESIGN.md`; add `manifest.json`, `tokens.css`, components, assets, or provenance when needed | [`design-systems/<brand>/`](design-systems/) |
   610→| A new **plugin** | Drop `open-design.json` + the type-specific payload under a category folder | [`plugins/community/`](plugins/community/) · spec in [`plugins/spec/SPEC.md`](plugins/spec/SPEC.md) · agent dev guide in [`plugins/spec/AGENT-DEVELOPMENT.md`](plugins/spec/AGENT-DEVELOPMENT.md) |
   611→| Support a new **coding-agent CLI** | One runtime definition + registry entry; add a parser only for a new wire format | [`apps/daemon/src/runtimes/defs/`](apps/daemon/src/runtimes/defs/) |
   612→| Fix a bug or polish UI | Browse the [`good-first-issue`](https://github.com/nexu-io/open-design/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22) label | [Issues →](https://github.com/nexu-io/open-design/issues) |
   613→| Translate the docs | Update the `README.<lang>.md` files | [`TRANSLATIONS.md`](TRANSLATIONS.md) |
   614→
   615→### 🤖 Contributing as an agent
   616→
   617→If *you are the agent reading this*, the fastest path is:
   618→
   619→```bash
   620→# 1. Boot locally
   621→git clone https://github.com/nexu-io/open-design.git
   622→cd open-design && corepack enable && pnpm install
   623→pnpm tools-dev run web
   624→
   625→# 2. Find a good-first-issue and assign yourself
   626→gh issue list --label "good first issue" --state open --limit 20
   627→gh issue develop <number>   # create a branch and worktree
   628→
   629→# 3. Make the change, run the checks
   630→pnpm guard && pnpm typecheck
   631→pnpm --filter @open-design/<package> test
   632→
   633→# 4. Open the PR
   634→gh pr create --fill
   635→```
   636→
   637→Full agent-friendly contribution flow, code style, and PR bar → [`CONTRIBUTING.md`](CONTRIBUTING.md) ([Deutsch](docs/i18n/CONTRIBUTING.de.md) · [Français](docs/i18n/CONTRIBUTING.fr.md) · [简体中文](docs/i18n/CONTRIBUTING.zh-CN.md) · [日本語](docs/i18n/CONTRIBUTING.ja-JP.md) · [한국어](docs/i18n/CONTRIBUTING.ko.md) · [Português](docs/i18n/CONTRIBUTING.pt-BR.md) · [ภาษาไทย](docs/i18n/CONTRIBUTING.th.md)).
